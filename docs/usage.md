# 校招海投助手 · 使用指南

面向日常投递操作的完整手册：从安装、建档，到一键填写、确认面板与记忆管理。

> 隐私提示：本扩展**零外发**——资料只存本机 `chrome.storage.local`，没有任何远程请求。结果面板底部始终显示「数据仅存本机，未上传任何网站。」

## 1. 安装扩展

### 方式 A：开发者加载（自用/开发）

1. 构建：在项目目录执行 `npm run build`（产物在 `build/chrome-mv3-prod`）
2. 打开 Chrome，地址栏输入 `chrome://extensions` 回车
3. 打开右上角 **「开发者模式」** 开关
4. 点 **「加载已解压的扩展程序」** → 选择 `build/chrome-mv3-prod` 文件夹
5. 工具栏出现「校招海投助手」图标；建议点拼图图标把它固定到工具栏

### 方式 B：zip 分发（给别人安装）

1. 执行 `npm run package` 生成 `build/chrome-mv3-prod.zip`
2. 解压 zip 后按方式 A 第 2~4 步加载解压目录

### 升级 / 修改代码后

`chrome://extensions` → 找到本扩展 → 点 **刷新图标（重新加载）**。
解压加载的扩展**不会自动热更新**，不重载会继续跑旧代码。

## 2. 准备资料（二选一）

点工具栏扩展图标 → **「打开资料管理」** 进入 options 页。

### 方式一：手动建档

1. 左侧导航六个分区逐个填写：
   - **基本信息**：姓名、性别、出生日期、手机号、邮箱、学校、专业、学历、政治面貌
   - **求职意向**：意向岗位、意向城市、期望薪资
   - **教育经历 / 实习经历 / 项目经历 / 获奖情况**：点「新增」填名称、方向/职位、开始/结束时间、描述
2. 顶部实时校验：手机号 `1[3-9]` 开头 11 位、邮箱格式、经历 `开始 ≤ 结束`，错了会逐字段红字提示
3. 点 **「保存全部修改」** → 显示「已保存 ✓」
4. 关闭标签页再打开，数据仍在（`chrome.storage.local` 持久化）

### 方式二：从简历导入（推荐）

1. 资料管理页 → **「从简历导入」** → **「选择简历文件」**
2. 支持**带文本层的 PDF、.txt、.md**；显示「解析中…（仅本地解析，不上传）」
3. 进入 **「简历导入核对」** 草稿页：
   - 「资料字段」：逐项检查，错了直接改；读不到的标 **「未读取到」** 请补填
   - 四类经历卡片：标题/方向/开始/结束/描述都可改；缺日期或低置信的带橙色 **「待核对」** 标记
4. 资料库已有数据时**必须选择导入方式**：
   - **「覆盖（整体替换）」**：旧资料全部清掉，以本次草稿为准 → **想刷新日期/修正旧数据用这个**
   - **「合并（保留手动确认的值）」**：已手动确认过的字段不被覆盖，只补空缺
5. 点 **「确认导入」**（或「丢弃草稿」放弃）

> 经验：发现条目日期丢失/数据过期时，**重载扩展 → 重新导入 → 选「覆盖」**，不要选合并（合并会保留旧的无日期条目造成重复）。

### 手工微调

资料管理四类经历列表支持每条：**编辑**（含「状态」改 已确认/待核对）、**删除**、**上移/下移** 排序。改完记得 **「保存全部修改」**。

## 3. 在网申页一键填写

1. 打开招聘站点的网申表单页（`http(s)://` 页面）
2. 点工具栏扩展图标 → **「一键填写」**
3. 状态区显示「已开始填写，请查看页面右下角结果面板」，popup 自动关闭
4. **3 秒内**页面右下角出现 **「填写结果」** 面板
5. 按面板提示处理：已填的核对一眼、`需确认` 的去页内面板点选、`需人工` 的自己动手

首次使用若资料库为空，popup 会提示 **「资料库为空：请先打开资料管理建档」** 并自动打开资料管理页；在 `chrome://` 等浏览器内部页会提示无法填写。

## 4. 看懂结果面板（5 类状态）

面板头部汇总：`已填 x · 待确认 x · 未找到 x · 缺资料 x · 需人工 x`

| 状态 | 含义 | 你要做的 |
|---|---|---|
| **已填写** | 高置信直接写入成功 | 扫一眼确认无误；手机号/邮箱是**掩码显示**（防偷窥） |
| **需确认** | 低置信/冲突/歧义，没有自动写 | 到页内确认面板点选（见下节） |
| **未找到** | 资料库有值，但页面上没找到对应字段（或匹配太弱不敢填，悬停条目可看原因） | 属正常（该站没这项）；持续全未找到见[故障排查](#10-故障排查) |
| **资料缺失** | 页面有字段，但资料库没值 | 回资料管理补填后再填一次 |
| **需人工处理** | 黑名单控件：提交按钮、密码、上传、协议勾选、验证码 | 自己手动操作——**扩展永不碰这些** |

已填写条目上有 **「记住本次修改」** 按钮（见第 6 节）。点「关闭」收起面板。

### 能自动填的控件类型

- **原生控件**：文本/电话/邮箱输入、下拉框、单选、多行文本（含 `input[type=date]`，资料库的「1999年9月1日」自动归一化为 `1999-09-01` 写入）
- **弹层下拉**（T066，牛客同款交互）：只读输入 + 点击后弹列表的自定义下拉（`div[role=combobox]`、AntD/Element 风格）——扩展会**自动点开 → 匹配选项 → 点选**；选项措辞对不上才转「需确认」
- **日历控件**（T067）：只读日期输入的自定义日历面板——自动打开、翻到目标年月、点选日期；打不开或选不到会降级「需人工」并附原因，不会静默丢失
- **级联下拉**（T068）：省→市这类联动下拉，子级选项会实时重读（扫描后的选项重建也能填对）
- **永不触碰**：密码、上传、验证码、协议勾选、提交按钮（黑名单，归「需人工处理」）

### 填写时的实时反馈（P2）

- **页面右下角进度条**：填写期间显示「已填 k/N · 匹配 m 项 · 当前：字段名」，带进度条；补扫轮也会接着累计
- **滚动跟随 + 黄色高亮**：每填一个字段，页面自动滚到该字段并给它 1.5 秒的黄色描边（`#f59e0b`），全程看得见它在填哪里
- **暂停按钮**：进度面板上的「暂停（剩余转需人工）」——点了之后剩余字段**一个都不碰**，统一归入「需人工」由你自己操作
- **popup 步骤清单**：点「一键填写」后 popup 不再自动关闭，四步实时更新（扫描页面 → 匹配资料 → 逐项填写 k/N → 完成汇总：已填·需确认·未找到·需人工）；关闭 popup 也不影响填写，页面面板照常更新

### 多段经历自动展开（P3）

- **资料里的经历条数 > 页面可见行数时**（很多站点一次只显示一条教育/实习经历），扩展会自动点该节的「+添加 / 新增 / 加一行」按钮把新行展开，再由补扫按行号填入第 2、3… 段经历
- **按钮认领规则**：按钮必须和某一类经历字段在同一个节容器里，容器里混着两类经历（歧义）就不点
- **安全边界**：`保存/提交/删除/上一步` 这类按钮永远不碰（黑名单）；每类经历最多点 5 次；点了没长出新行立刻停；已点「暂停」则不展开
- 页面若没有可识别的「添加」按钮（或一次展示全部条目），行为与从前一致：只填可见行

## 5. 页内确认面板

当出现 `需确认` 条目时，填写结束后页面上会弹出 **「需要你确认（n）」** 面板（头部附本次统计：已填/未找到/需人工）。卡片按原因**分组展示**：标签歧义 → 页面已有值冲突 → 选项措辞不一致 → 资料库待核对，每组带计数；标题显示可读的中文字段名，页面原始标识降级为「页面字段：」副行。

- **有候选值**：点击候选 → 立即填入页面，并自动记入字段记忆（`user_confirm`）
- **无候选 / 想换值**：在「无候选，请输入值…」框输入 → 点 **「填入」**
- **歧义字段**（提示"可能对应多个字段"）：手动选择正确的那个
- **拿不准**：点 **「跳过（保持页面原状）」**——跳过**不会**写入记忆（FR-023）
- 全部处理完点 **「关闭」**；结果面板会同步刷新条目状态

> 冲突场景（页面已预填且与资料库不一致）：扩展**不覆盖**（FR-017），转为需确认，由你决定用哪个值。
>
> **不会来烦你的东西**（T058 降噪）：仅靠 name/id 猜出来的弱匹配（如 `userPhone` 这类无标签输入）**不再弹确认**，直接归「未找到」；「是否投过其他岗/是否国内手机」这类**是/否勾选题**资料值本来答不了，也不会进确认面板。

## 6. 「记住本次修改」与字段记忆

字段记忆 = 「这个页面控件该填什么」的本机备忘，按**字段签名**（标签+控件类型+name/id+选项指纹）存取。

- **记忆命中 → 下次同结构字段直接填**，不再弹确认（FR-021）
- 写入记忆只有两个入口，**没有任何自动学习**：
  1. 确认面板点选「填入」→ 记为 `user_confirm`
  2. 结果面板已填写条目上的 **「记住本次修改」** 按钮 → 把该字段**页面上的当前值**记为 `user_edit`（仅点击瞬间读取，未点击绝不写入，FR-020）
- 页面点了「跳过」→ 不写入（FR-023）
- 歧义标签的字段即使有记忆，仍会询问（FR-022）
- 容量：最多 2000 条，超限按最久未用淘汰（LRU）

典型用法：第一次在某招聘网站逐项确认完，点过「记住本次修改」后，下次同站点同表单基本一键直填。

## 7. 多步 / 动态表单

- 分步提交的表单（第一步/第二步字段不同），切到新步骤后再点一次「一键填写」
- 页面**运行中动态追加**的字段（懒加载、点"添加"出现）会被自动补扫：
  主窗口观察 3 秒 + 有变更再补扫最多 5 秒（300ms 防抖，FR-016）
- 补扫超出预算还没出现 → 再点一次「一键填写」即可

## 8. 各类控件的处理方式

| 页面控件 | 处理 |
|---|---|
| 文本框 / 电话 / 邮箱 / 文本域 | 原生 setter + 事件派发，兼容 React/Vue 受控组件 |
| 下拉 `<select>` | 自动等价映射（如 资料"本科" ↔ 页面"Bachelor"/"学士"）；措辞对不上 → 转确认不硬填 |
| 单选 radio（如 性别） | 按组识别，选项等价才填 |
| 复选 checkbox | 普通勾选可填；协议类黑名单跳过 |
| 页面预填的值 | **与资料库不一致就不覆盖**（FR-017），转确认 |
| `readonly` 输入框（点开弹层选日期/学校的那种） | 按设计**不自动填**，归「需人工」——这类控件需你在页面弹层里选 |
| iframe 内的表单 | v1 只扫顶层页面（`all_frames: false`），iframe 内字段扫不到 |
| 表格型经历表 | 按行号对应资料库同序号经历（第 1 行对第 1 条） |

## 9. 数据存放与清除

| 数据 | 位置 | 上限 |
|---|---|---|
| 资料库 + 经历条目 | `chrome.storage.local` | — |
| 字段记忆 | 同上 | 2000 条 LRU |
| 填写报告（掩码） | 同上 | 最近 20 条 |
| 简历草稿 | 同上 | 单例（确认或丢弃即清） |

- **全部重置**：卸载扩展即清除其本地存储；重新安装后重新建档/导入
- **只重置资料库**：重新「从简历导入」并选「覆盖」
- 数据从不出本机；卸载前无需担心"云端残留"（因为从来没有云）

## 10. 故障排查

| 现象 | 原因 / 解法 |
|---|---|
| 改了代码或更新版本后行为没变 | `chrome://extensions` → 点扩展的**重新加载**（解压扩展不热更新） |
| 导入的条目没有开始/结束时间 | 旧版本导入的脏数据 → **重载扩展 → 重新导入 → 选「覆盖」** |
| 结果面板全是「未找到」 | ① 资料库是否已建档；② 字段是否为 readonly 弹层控件（归需人工）；③ 字段是否在 iframe 内 |
| 提示"无法提取文本" | 扫描件/图片 PDF 没有文本层（设计如此）→ 换文本型 PDF 或用 .txt 导入 |
| 点「一键填写」提示 TAB_UNAVAILABLE | 当前标签是 `chrome://` 等浏览器内部页，打不开网申表单 |
| 面板没出现 | 看 popup 状态区报错；`NO_PROFILE` 会自动带你去建档 |
| 某招聘链接 404 | 站点短链过期/一次性链接，与扩展无关 |
| 想让它别动某个字段 | 那字段会出现在「需人工」或确认面板里点「跳过」；黑名单控件（提交/密码/验证码/协议）天然不会被碰 |
